ФИНАНСЫ ПО ЗАКАЗАМ — FIREBASE / FIRESTORE (ТЕСТОВАЯ СБОРКА)
==============================================================

1. ЧТО ЭТО
Сайт для Windows и Android (PWA). Данные хранятся в Cloud Firestore
проекта finansypozakazam, а не в Google Диске. Вход — через Firebase
Authentication (Email/Password). Офлайн-изменения сохраняются в браузере
и отправляются после появления связи.

ВАЖНО: Эта сборка не проверялась на настоящем Firebase-аккаунте или
двух реальных устройствах. Это проект для тестирования.
НИЧЕГО НЕ УДАЛЯЙТЕ из старой программы, GitHub и Google Диска.

2. КАК БЕЗОПАСНО ПРОВЕРИТЬ
- Сначала сохраните резервную копию данных в старой программе.
- НЕ заменяйте файлы репозитория finansy-po-zakazam.
- Создайте ОТДЕЛЬНЫЙ репозиторий GitHub, например
  finansy-po-zakazam-firebase-test (Public для GitHub Pages).
- Загрузите содержимое этой папки в корень нового репозитория:
  index.html, sw.js, manifest.webmanifest, .nojekyll, папку assets.
- В Settings → Pages установите Deploy from a branch / main / (root).
- Адрес будет примерно:
  https://farhodkb-oss.github.io/finansy-po-zakazam-firebase-test/
- Откройте сайт и войдите через email и пароль, которые вы создали
  в Firebase Console → Authentication → Users.

3. FIREBASE КОНФИГУРАЦИЯ
Параметры проекта уже внесены в assets/firebase_bridge.js.
Веб-ключ apiKey — публичная конфигурация, НЕ пароль. Доступ к базе
ограничивается Firestore Security Rules. Не загружайте Client Secret,
пароли, SQLite или финансовые JSON-файлы на GitHub.

Для Firestore должны оставаться правила, которые разрешают только
доступ к users/{uid}/... при request.auth.uid == uid:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}

Нельзя ставить «allow read, write: if true».

4. ПЕРЕНОС СТАРОЙ БАЗЫ
- Дождитесь первой загрузки Firebase. Новая база должна быть пустой.
- В СТАРОЙ действующей программе с Google Диском дождитесь статуса
  «Синхронизировано». Затем выберите «Настройки → Скачать JSON».
  Это актуальная резервная копия всех текущих данных с устройства.
- В НОВОЙ Firebase-программе выберите «Настройки → Импорт JSON»
  и этот свежий файл (формат finansy-offline-backup-v1).
- АЛЬТЕРНАТИВА: если данные со времени прежнего экспорта не менялись,
  можно выбрать созданный ранее файл из Windows-версии:
  C:\MY PROGRAMM\FINANSY_GOOGLE_DRIVE\IMPORT_IZ_WINDOWS.json
- Не загружайте файлы с финансами на GitHub! Импортируйте один раз.
- Дождитесь «Синхронизировано» и проверьте данные.
- По исходным показателям ожидается:
  2 заказа, приход 50 630 000 сум, расход 26 462 000 сум,
  разница 24 168 000 сум (за период 01–13.10.2026).
- В другом браузере/на телефоне зайдите под тем же Firebase UID:
  данные должны появиться после загрузки.

5. ОФЛАЙН-ПРОВЕРКА
- Первый вход требует интернета.
- Откройте приложение ONLINE, дождитесь данных; чтобы CDN-модули
  гарантированно попали в PWA-кэш, откройте страницу ещё раз ONLINE.
- Выключите интернет, перезапустите приложение, добавьте ТЕСТОВУЮ
  операцию, проверьте сохранение. Затем включите интернет.
- Подождите исчезновения «Ожидает отправки». Проверьте с другого
  устройства и убедитесь, что тестовая операция появилась один раз.
- Если соединения нет, НЕ выходите из аккаунта и НЕ очищайте данные
  сайта/приложения до успешной отправки очереди.
- Браузер может самостоятельно удалить локальное хранилище при
  недостатке места или очистке данных. Нужны резервные копии.

6. ОСОБЕННОСТИ
- Все 7 справочников, заказы, операции, отчёты CSV и печать в PDF
  сохранены. PDF формируется через печать браузера.
- События хранятся в users/{UID}/events/{EVENT_ID}. Их уникальные ID
  защищают от дублирования повторных отправок.
- Если два устройства изменили одну запись параллельно, раздел
  «Настройки» покажет конфликт версий для ручного выбора.
- Полного серверного теста и испытания на Android ещё НЕ было.
- Тестовый репозиторий НЕ меняет рабочую программу с Google Drive.

7. ДИАГНОСТИКА
- Если видите Firebase permission-denied — проверьте правила Firestore,
  текущую учётную запись и UID.
- Если вход выдаёт auth/invalid-credential — проверьте email и пароль.
- Если page загрузилась, но SDK не работает — проверьте интернет,
  ошибки консоли (F12 → Console) и доступ к www.gstatic.com.
- Если GitHub Page не обновился — дождитесь Actions → Pages,
  обновите сайт Ctrl+Shift+R; НЕ очищайте данные сайта без резервной копии.
- Из-за Firestore offline persistence на некоторых устройствах/в
  приватных режимах офлайн-хранилище может работать не полностью.

ПОСЛЕ успешных тестов можно будет обновить основной GitHub-репозиторий.
